# Collaboration and conflict resolution
If Tasarım Vergisi or another design skill is actually installed, use it for composition, typography, visual language and motion; Beyin-Bedava owns gameplay intent, mechanics, progression, fairness and test hypotheses. Agree on shared Game DNA and file ownership before edits. Resolve contradictions by user constraints, accessibility, gameplay readability, then measured evidence. One writer per file/slice; use actual host capabilities, not invented multi-agent concurrency. If unavailable, follow local game-feel guidance and report the limitation.

Use owner IDs `beyin-bedava` and `tasarim-vergisi` in a single workspace ledger. List canonical repository-relative files in the plan. The ledger rejects duplicate paths and prevents dependent tasks from starting before their prerequisites are verified. Each skill claims its own task and runs `check-files` on the intended write set before editing and on the changed paths before finishing. Review cross-skill changes through evidence or a proposal, with writes routed through the owner. If ownership changes, use `handoff ID OWNER "reason"` while the task is pending or blocked. For a running task, record a checkpoint and release it with `fail` before handoff. Keep shared files under one owner for the slice. The protocol requires both skills to cooperate with the checks.
