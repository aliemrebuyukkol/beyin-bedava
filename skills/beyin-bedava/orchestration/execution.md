# Scoped autonomous execution and recovery
1. Read current branch/status and project docs; do not reset, stash, force-push or overwrite user work. Record baseline and constraints. 
2. For multi-step tasks maintain a local, non-secret task ledger (suggested .beyin-bedava/state.json, ignored if appropriate): goal, baseline revision, tasks with IDs, dependencies, status (pending/in_progress/verified/blocked), touched files, acceptance, commands/results, blockers, next action. Atomic write; never store credentials or raw player data. On resume re-read current files and git status before trusting ledger.
3. Work by vertical slice and dependency order. Run relevant tests per slice; distinguish not run, failed and passed. On failure inspect root cause and fix within scope; after two repeated identical failures change approach or mark blocker. Avoid endless retries and unnecessary rewrites.
4. If user decisions are not essential, pick a reversible default and disclose it. Ask only for irreversible scope, live payments, secrets, destructive changes or genuinely blocked work. Continue independent tasks when possible.
5. Before commit inspect diff, test and document evidence. Only commit/push when requested or authorized. No force pushes. If interrupted, return exact checkpoint and next command. A ledger does not schedule work or guarantee host resume.

Use `scripts/task_ledger.py` for a persistent SQLite ledger. The plan provides `goal`, `baseline` (the Git revision) and `tasks`. Each task has `id`, `owner`, `acceptance`, optional `depends`, `files` and `max_attempts` (default 3). Initialize with `init plan.json`. Use `status` or `ready [--owner OWNER]` to list all parallelizable branches ready to run right now, then `claim OWNER --task ID` or claim the next ready task without an ID. Use the returned token for `checkpoint ID TOKEN '{"next":"run test","completed":["implemented movement"]}'`, `check-files ID TOKEN path/to/file` and `finish ID TOKEN "command, observed result and evidence reference"`. Evidence is operator-supplied. Use `fail ID TOKEN "actual cause"` to retry or block at the attempt limit. Recover a blocked task with `reopen ID "cause addressed"`.

## Branching multi-agent execution & 100% completion loop
1. **Itemize all capabilities upfront:** Run `python3 scripts/plan_game_integration.py plan <workspace> --goal "<goal>" --all-capabilities --branch-agents [--new-project] [--monetization-choice ask|none|ads|paywall|both] --output /tmp/bb-plan.json` and initialize the ledger (`python3 scripts/task_ledger.py --db /tmp/bb-tasks.sqlite init /tmp/bb-plan.json`). Every skill capability is mapped to a dedicated specialist owner (`discovery-agent`, `research-agent`, `dna-design-agent`, `progression-economy-agent`, `feel-ui-agent`, `monetization-gate-agent`, `engine-build-agent`, `audit-safeguards-agent`, `qa-verification-agent`, `beyin-bedava`).
2. **Post-approval Ad & Paywall decision gate (`monetization-gate-agent`):** In Wave 1 (`branch_monetization_gate`), when `--monetization-choice ask` (the default) is active and the project is approved, `monetization-gate-agent` asks the user whether they want **Ad Placements** (opt-in rewarded, natural-boundary interstitials with 2-loss suppression, safe banners) and/or **Paywall / IAP Screens** (real-money pricing, aligned packs, 2-step confirmation, drop odds/pity, Restore Purchases). Based on the user's answer (`none`, `ads`, `paywall`, or `both`), it either skips monetization (`adPlacements.enabled=false`, `purchaseScreens.enabled=false`) or activates the corresponding ethical modules in `wire` and `branch_capability_audits`.
3. **Fan out parallel branches:** Query `python3 scripts/task_ledger.py --db /tmp/bb-tasks.sqlite ready` at each wave. For every ready task, branch out via host subagents (`invoke_subagent` or `run_workflow` `parallel(...)`) with explicit single-writer file ownership (`--own TASK PATH` and `check-files`).
4. **100% Completion & Recursive Self-Heal:** After each wave or full pass, run `python3 scripts/task_ledger.py --db /tmp/bb-tasks.sqlite audit-completion --restart-incomplete` (or run `python3 scripts/plan_game_integration.py autopilot <workspace> --goal "<goal>" --db /tmp/bb-tasks.sqlite --max-cycles 3`). When `complete` is `false` (exit code `1`), any blocked, failed, or unverified task (and its downstream dependents) is automatically reopened to `pending` so the responsible branch restarts immediately until `completion_pct == 100.0` (`complete: true`).

Expired leases free incomplete tasks for retry and retain the last checkpoint. Re-read the working tree and Git baseline before repeating side effects. Renew leases by checkpointing before a long operation. Tokens fence stale workers from changing ledger state. They do not mediate operating-system writes or schedule host sessions.
