# Native Apple games (Swift)
Detect .swift sources with SpriteKit, RealityKit or SceneKit game evidence; a SwiftUI app or RealityKit viewer alone is not proof of a game. Inspect Xcode targets, deployment target and existing frameworks. Keep SwiftUI presentation separate from simulation; use SpriteKit scene/update and physics contacts for 2D; RealityKit entity/component/system and collision events for 3D; SceneKit existing projects only, verify current SDK status before new use. Respect main-actor UI updates and avoid per-frame allocations or publishing every tick. Use fixed-step simulation when needed, seeded RNG for tests, explicit pause/resume and safe-area input. No forced engine migration.
For StoreKit 2 use localized Product.displayPrice, verified transactions, current entitlements and explicit restore/sync; use existing RevenueCat if present instead of duplicate entitlement logic. Mock providers only in test builds, idempotent reward grants, no secrets in client. Check platform policies before release. XCTest/Swift Testing and Xcode build/test commands appropriate to actual scheme; run on simulator and physical device for haptics, GPU, thermal and performance. Document if Xcode or devices unavailable.
